# RakshaNet Hackathon Demo Runbook

Last updated: 2026-08-17

## Target duration

Three minutes, with a recorded backup video and a manual scenario fallback.

## Cast

- Website: Authority/control room.
- Redmi Note 10 Pro: internet-connected gateway and community member `Aman`.
- Samsung Galaxy J8: internet-disabled community member `Home`.
- Optional Galaxy A17: Ambassador/relay node when available.

## Preflight

- Install the same versioned APK on every phone.
- Join `RakshaNet Demo Network` and verify the network-health control is green.
- Keep internet available only on the gateway phone.
- Confirm the website health panel sees the control plane and flood model.
- Clear only demo incident data, not signing identity/trusted peers.
- Prepare Normal and Extreme rainfall presets.
- Record a complete successful backup once before presenting.

## Live story

### 0:00–0:25 — Prepare

Show the redesigned Home and Learn journey. State that lessons and progress are
available offline and safety content is sourced.

### 0:25–0:55 — Detect and start a drill

On the website, choose `Extreme rainfall` and evaluate the historical-risk
model. Clearly point to `DEMO / SIMULATED TELEMETRY`. Start `Kerala Flood Drill`.

Expected evidence:

- Website shows an active drill and created cloud event sequence.
- Redmi changes to active-incident Home.
- Samsung receives the same incident through nearby mesh with internet off.

### 0:55–1:35 — Community intelligence

On Samsung, submit a structured field update such as “Water above ankle level
near school road; route partially blocked.”

Expected evidence:

- Samsung shows stored/reached-peer evidence truthfully.
- Redmi receives the update through mesh.
- Gateway uploads it and the authority website displays the same report ID.

### 1:35–2:10 — AI-assisted report

Generate a situation report. Show confirmed facts, urgent needs, contradictions,
unverified claims, and source report IDs. Say explicitly that it is a draft.

The authority edits or approves the message: “Avoid School Road. Move toward
the community hall using the east route. This is a drill.”

### 2:10–2:40 — Authority to offline mesh

Broadcast the approved instruction.

Expected evidence:

- The control plane signs and sequences the event.
- Redmi verifies and injects it into the mesh.
- Samsung displays it as an Authority bulletin while remaining offline.

### 2:40–3:00 — Close

Show network health and explain that any connected phone can become a gateway;
nearby phones continue carrying messages if internet disappears.

## Fallback ladder

1. If model inference fails, use a labelled manual `Extreme flood drill` preset.
2. If cloud-to-phone sync is slow, tap `Sync now` on the gateway diagnostics
   sheet; do not restart the app.
3. If a nearby link is absent, show the stored outbox then rejoin the known demo
   network; do not claim delivery until observed.
4. If AI analysis fails, show raw reports and use the pre-written authority
   guidance template.
5. If the live environment fails completely, play the recorded end-to-end demo
   and then show the source/evidence screens.

## Claims allowed

- Offline nearby messaging was physically verified on three Android phones.
- A connected gateway can bridge approved cloud events into the nearby mesh
  once this vertical slice is physically demonstrated.
- Model output is decision support based on 118 annual Kerala observations.
- AI assists with summarization; a human authority approves broadcasts.

## Claims not allowed

- Government deployment or verified government identity.
- Real-time flood forecasting from live sensors.
- Guaranteed delivery to every person or optimal routing across a city.
- Autonomous AI emergency decisions.
- End-to-end confidentiality for private messages.
